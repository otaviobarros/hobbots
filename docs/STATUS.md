# Status

What Hobbots does today, split into what has been proven end to end and what has not. Each item has the date it last changed and the issue that tracks it. A proven item links its [evidence record](evidence/README.md), which names the commit and setup it ran on.

Hobbots is an early build. Only macOS on Apple silicon has been checked by hand. Linux, Windows and Intel Macs have not.

## What works

Proven end to end, on the setup its record names.

- **2026-10-28 · Database suites run on SQLite and PostgreSQL.** The persistence and server suites run on both databases on every pull request and push to `main`. ([#19](https://github.com/otaviobarros/hobbots/issues/19), [CI workflow](../.github/workflows/ci.yml))
- **2026-10-29 · The background service keeps running after the window closes.** A reply completes after the window closes, a second launch starts no second server, and Quit stops the server. The app registers itself to open at login. ([#49](https://github.com/otaviobarros/hobbots/issues/49), [evidence](evidence/2026-10-29-background-service.md))
- **2026-10-30 · A new installation goes from Welcome to Home.** Setup and the first hob work in a browser against a hub from source, and the hub opens on Home after a restart. A missing or signed-out Claude Code blocks setup and shows its fix. ([#70](https://github.com/otaviobarros/hobbots/issues/70), [evidence](evidence/2026-10-30-first-launch.md))
- **2026-10-31 · Several hobs chat, edit and retire independently.** Hobs on different models reply at once on their own threads. An edit mid-reply reaches only that hob's next reply, in the same thread too, on real Claude Code. A retired hob refuses messages and keeps its threads readable. ([#87](https://github.com/otaviobarros/hobbots/issues/87), [#164](https://github.com/otaviobarros/hobbots/issues/164), [evidence](evidence/2026-10-30-multi-hob.md), [evidence for the fix](evidence/2026-10-31-hob-edits-existing-threads.md))
- **2026-10-31 · Chat survives a crash, time offline and an expired cursor.** A reply cut off by a killed hub keeps its saved text, a page that reconnects replays exactly what it missed, and a page away past retention or after a restored backup loads the thread again. Each message shows once. Checked with the fake runtime, in the browser on SQLite and at hub level on SQLite and PostgreSQL. ([#118](https://github.com/otaviobarros/hobbots/issues/118), [evidence](evidence/2026-10-31-reliable-chat.md))
- **2026-11-01 · Hobs use tools within their folders, under the policy.** Under Balanced a hob edits and runs tests in its folder without asking, a read outside its folders is refused whatever the prompt says, and an Ask action holds its turn until the user allows it once or denies it in chat. Checked with the fake runtime, in the browser on SQLite and at hub level on SQLite and PostgreSQL. ([#8](https://github.com/otaviobarros/hobbots/issues/8), [#137](https://github.com/otaviobarros/hobbots/issues/137), [evidence](evidence/2026-11-01-tools-under-policy.md))
- **2026-11-01 · A hob signs commits with the user's 1Password key, when the user turns it on.** On macOS, a hob with the switch on makes signed commits inside the sandbox, one with it off makes unsigned ones, and only the signing hob reaches 1Password's agent. Linux keeps signing off. ([#234](https://github.com/otaviobarros/hobbots/issues/234), [evidence](evidence/2026-10-31-1password-signing.md))
- **2026-11-01 · Only the user decides approvals and manages grants.** A script, another web page or a hob's tool call cannot decide a request, save or remove a grant, or widen a hob's or the setup's permissions; each attempt is refused and logged. On macOS a real Claude Code hob's `curl` with a forged origin never reaches the hub. Until device tokens exist, an unsandboxed hob is not covered. ([#216](https://github.com/otaviobarros/hobbots/issues/216), [evidence](evidence/2026-11-01-agents-cannot-grant.md))
- **2026-11-01 · Approvals hold from the chat and the Inbox.** An Always rule shows in History and answers the next matching action until it is removed, a double click runs the action once and saves one rule, a request nobody decides for a day expires and cannot be approved, and deciding in the Inbox gives the same result as in the chat. Checked with the fake runtime, in the browser on SQLite and at hub level on SQLite and PostgreSQL. ([#9](https://github.com/otaviobarros/hobbots/issues/9), [#217](https://github.com/otaviobarros/hobbots/issues/217), [evidence](evidence/2026-11-01-approvals-end-to-end.md))
- **2026-11-01 · Threads are archived, found and restored without losing history.** An archived thread leaves the hob's list, is found in its Archived list and by search, opens read-only and comes back whole on Restore. Archiving is refused while a reply runs or an approval waits, and never interrupts either. Checked with the fake runtime, in the browser on SQLite and at hub level on SQLite and PostgreSQL. ([#252](https://github.com/otaviobarros/hobbots/issues/252), [#257](https://github.com/otaviobarros/hobbots/issues/257), [evidence](evidence/2026-11-01-archive-threads.md))

## Not proven yet

Built, but not proven end to end, or proven only in part.

- **2026-11-02 · You connect GitHub on the hub, and choose which hobs use it.** Settings › Charms connects the Hobbots GitHub App with GitHub's device flow, keeping its tokens in the OS keychain and refreshing them on the hub, or uses the GitHub CLI's or Git's own sign-in already on the computer. Each hob's Charms tab grants the GitHub Charm; a hob without it, or a hub with nothing connected, is offered none of its actions from the next turn. Proven with stand-ins for GitHub, the keychain tools and the fake runtime; the Hobbots GitHub App is not registered yet, and no real device flow, keychain or Claude Code turn is verified. ([#322](https://github.com/otaviobarros/hobbots/issues/322))

- **2026-10-29 · Opening at login after a real log-out.** The log-out and log-in steps of the background service were never run on a real Mac. ([#49](https://github.com/otaviobarros/hobbots/issues/49), [evidence](evidence/2026-10-29-background-service.md#gaps))
- **2026-10-29 · The release workflow.** It packages, smoke-tests and drafts a release on a version tag, but no tag has run it yet, so the packaged checks have run only on a maintainer's Mac. ([#34](https://github.com/otaviobarros/hobbots/issues/34))
- **2026-10-29 · Required checks on `main`.** The ruleset is written but not yet required. ([#22](https://github.com/otaviobarros/hobbots/issues/22))
- **2026-10-30 · First launch on the packaged app with a real Claude Code login.** Only the browser flow with the fake runtime is recorded. ([#70](https://github.com/otaviobarros/hobbots/issues/70), [evidence](evidence/2026-10-30-first-launch.md#gaps))
- **2026-11-01 · Tools under policy on real Claude Code.** Claude Code tools run under the policy and the sandbox, and [ADR 014](decisions/014-tool-policy-and-enforcement.md#what-131-verified) records what was checked by hand on macOS before asking existed. The [manual checklist](evidence/checklists/tools-under-policy.md) for the same checks, Ask included, has not been run yet. The Push Charm is built, and not verified on real Claude Code. ([#8](https://github.com/otaviobarros/hobbots/issues/8), [#225](https://github.com/otaviobarros/hobbots/issues/225), [evidence](evidence/2026-11-01-tools-under-policy.md#gaps))

- **2026-11-01 · Switching a thread's brain.** A thread can move to another runtime or model and keep its context through a briefing the hub writes, proven with the fake runtime standing in for Claude Code and Codex. The Codex adapter is not built, so a real hub can only switch Claude Code models. ([#169](https://github.com/otaviobarros/hobbots/issues/169), [#12](https://github.com/otaviobarros/hobbots/issues/12))

- **2026-11-01 · Hob tools for Tasks and Quests.** Hobs can plan steps, start a Quest, delegate, report, ask, answer, escalate, hand off, wait, complete and cancel through tools the hub checks. Proven at hub level with the fake runtime on SQLite and PostgreSQL. Chat turns and steps offer them; serving them to a real Claude Code is not verified. ([#271](https://github.com/otaviobarros/hobbots/issues/271), [#273](https://github.com/otaviobarros/hobbots/issues/273))

- **2026-11-01 · A Task's steps run in fresh sessions.** A hob splits the request it is working on into steps; each runs in a session of its own from its brief, within limits per hob and per request, while the hob keeps chatting, and the hob gets back their checkpoints and results, never their sessions. Proven at hub level with the fake runtime. A step cannot ask for approval or ask a question, and real Claude Code is not verified. ([#272](https://github.com/otaviobarros/hobbots/issues/272), [#292](https://github.com/otaviobarros/hobbots/issues/292))

- **2026-11-01 · A hob's backpack is recorded.** A delegated Task, a result, a failure, a report, a question, an answer and a hand-off each land in the backpack of the hob that has to deal with them, in the same transaction as the change. A retried tool call records nothing new, and a write under a stale claim is refused. An item is delivered at least once and processed once: dispatching it twice runs one turn, a turn that ends early is retried with backoff, and a result for a cancelled Task resolves as late without a turn. The backpack is proven at the repository and hub level, and delivery at the repository level, on SQLite and PostgreSQL. ([#290](https://github.com/otaviobarros/hobbots/issues/290), [#291](https://github.com/otaviobarros/hobbots/issues/291), [#292](https://github.com/otaviobarros/hobbots/issues/292))

- **2026-11-02 · A hob continues when work arrives.** Work that reaches the hob running your request after its turn ended, such as a step's result or failure, starts a turn in its thread without you prompting, and that turn can finish the request. A message you queued starts first, with the work riding along. A paused hob keeps the work until it wakes, a turn you stop holds its work back until you write again, and an approval request a restart cut off reaches its hob as such. Proven at hub level with the fake runtime. Routine progress starts no turn: however many updates pile up, they reach the hob as one digest, a line per Task, in its next turn, whether that is a continuation or your next message. Real Claude Code is not verified, and a member's Task does not wake its own session yet. ([#292](https://github.com/otaviobarros/hobbots/issues/292), [#293](https://github.com/otaviobarros/hobbots/issues/293), [#273](https://github.com/otaviobarros/hobbots/issues/273))

- **2026-11-02 · Stuck work becomes a blocker.** Work a hob was handed whose every try ended early, including work you stopped each time, and work whose hob retired, no longer disappears: it shows as stuck on its Task card and in Inbox › Needs you with a next action, and you retry or dismiss it, each choice kept. How many tries an item gets is configurable. Proven at repository level on SQLite and PostgreSQL, at hub level and in the browser with the fake runtime. Reassign waits for Task reassignment, and missing authority or an unavailable runtime raise no blocker yet. ([#296](https://github.com/otaviobarros/hobbots/issues/296), [#311](https://github.com/otaviobarros/hobbots/issues/311))
- **2026-11-02 · Nothing is lost when Hobbots restarts.** Stopping Hobbots between a step finishing and its hob hearing of it loses nothing: at the next start, claims the earlier process held are expired with a new fencing token, a cut-off continuation runs again, and a step the stop cut off, or whose session ended just before it, fails so its hob hears of it. Proven at hub level with two hubs started one after the other on one database, with the fake runtime. A real crash of the packaged app is not verified. ([#295](https://github.com/otaviobarros/hobbots/issues/295))

- **2026-11-01 · Hobs read their repository's issues and pull requests on GitHub.** The GitHub Charm reads the repository of a hob's own folder, its issues and its pull requests on the hub with the user's GitHub sign-in, so no credential reaches the sandbox, under the hob's Read GitHub rule. Proven with a stand-in for GitHub and the fake runtime at hub level; a real Claude Code turn with a real sign-in is not verified. ([#317](https://github.com/otaviobarros/hobbots/issues/317), [#325](https://github.com/otaviobarros/hobbots/issues/325))
- **2026-11-02 · Hobs push a branch to GitHub through the Charm.** Under Balanced a push asks and sends exactly the commit the card showed, a force push or one to the default branch asks once only, and a `git push` command points to the Charm. The hub pushes from its own staging copy, so no hook or setting from the hob's repository runs, over HTTPS with the hub's sign-in or over SSH through the user's agent. A push whose answer is lost is read back on GitHub and stays uncertain until found or settled by the user. Proven with a stand-in for GitHub and the fake runtime; a real Claude Code turn and a real GitHub are not verified. ([#323](https://github.com/otaviobarros/hobbots/issues/323), [#325](https://github.com/otaviobarros/hobbots/issues/325))
- **2026-11-02 · Hobs open pull requests and comment through the Charm.** Under Balanced each asks, and the card shows the title, the start of the body or the comment after redaction, which is exactly what is sent. A retried call returns its first answer, and one whose answer is lost is read back on GitHub: a pull request from that head opened by your account after the call, or a comment carrying the call's hidden marker. Proven with a stand-in for GitHub's API at hub level; the fake runtime end to end, a real Claude Code turn and a real GitHub are not verified. ([#324](https://github.com/otaviobarros/hobbots/issues/324), [#325](https://github.com/otaviobarros/hobbots/issues/325))

- **2026-11-01 · Work is done only when nothing is left open.** Completing a Task or a Quest is refused while work under it, a wait, a dependency, a question, a milestone, a pending approval or an unread backpack item is still open, and the refusal names up to eight of them and counts the rest. The hub reads the same responsibility ledger without asking the hob. The turn that finishes a Task consumes the items it carried in the same transaction. Proven at repository and hub level with the fake runtime on SQLite and PostgreSQL. A member's Task has no turn of its own to complete from yet. ([#294](https://github.com/otaviobarros/hobbots/issues/294), [#292](https://github.com/otaviobarros/hobbots/issues/292))

- **2026-11-02 · A lead runs a party on a Quest.** A hob you ask brings in other hobs, each of which works on its Task in its own session, in parallel, under its own policy narrowed by the delegation. A member's approval asks you, not its lead. A member that comes after another waits, and gets that result only when the lead hands it on; the lead keeps answering you while it waits, and wraps up in your chat once every member is done. Proven at hub level with the fake runtime on SQLite and PostgreSQL. Real Claude Code is not verified, and This Task grants are not built yet ([#352](https://github.com/otaviobarros/hobbots/issues/352)). ([#273](https://github.com/otaviobarros/hobbots/issues/273))
- **2026-11-02 · Questions and notes reach the right hob.** A member's question goes to its lead, who answers it or passes it up; one no lead can answer waits for you on the card in the lead's chat and in the Inbox's Needs you, and your answer goes back to the hob that asked, in its own session. A note you leave on a member's Task reaches its lead as a message about that Task, once. A finding, blocker or milestone wakes the lead; routine progress only rides along. Proven at hub level with the fake runtime on SQLite, and in the browser for the Inbox and the drawer. PostgreSQL and real Claude Code are not verified. ([#274](https://github.com/otaviobarros/hobbots/issues/274))

Other runtimes, the Workbench and remote access are not built yet. The [slices](https://github.com/otaviobarros/hobbots/issues?q=label%3A%22type%3A+slice%22) list them in order.
