# Design specification

Decided in [ADR 008](../decisions/008-design.md). This document records what the code must match. The [screen inventory](screens-and-flows.md) lists every screen and its states.

Hobbots is a modern AI chat app with a pixel-folklore character: small hobs that work at night in a lantern-lit workshop. Familiar interactions come first. The art, the hob animations and the names carry the personality; they never hide what a hob or an action actually does.

## Style tokens

| Token | Value | Use |
|---|---|---|
| Ground | `#141228` | App background, text on lantern and mint |
| Deep | `#0d0c1c` | Rail, title strip, inputs, scenes |
| Panel / Card | `#1b1835` / `#1f1c3e` | Side panels / cards |
| Hover | `#25224a` | Row and button hover |
| Line / Line 2 | `#2c2a5a` / `#3a3666` | Dividers, selected fill / selected thread, quiet borders |
| Control | `#7770c4` | Input and secondary-button borders (3:1+) |
| Text / Secondary / Label | `#ece8ff` / `#c9c3e8` / `#a9a2e0` | Reading text / supporting text / labels and timestamps |
| Moonlight | `#f3e9b5` | Selected item, hob names, focus ring |
| Lantern | `#f2a541` (hover `#ffb75c`, press edge `#9a5f16`, link hover `#ffc477`) | Primary action, links, "needs you" |
| Mint | `#7fd1b9` (deep `#3f8a75`) | Working, done, approve |
| Rose | `#ee9292` | Deny, stop, error |

Status tags: Working (mint on ground), Running (mint deep), Waiting and Needs you (lantern), Queued (line 2), Cancelled (line 2 with secondary text), Archived (line 2 with secondary text), Failed (rose). Unsandboxed (rose outline on ground) marks a hob running without the sandbox; Needs the sandbox (line 2 with secondary text) marks an action blocked because the sandbox is unavailable. Workbench view labels: Live (mint), Screenshot (`#8fb4f0`, with age), History, Unavailable (with reason), Later. Provider tiles: Claude C `#e39a74`, ChatGPT G `#8fd3a8`, Gemini G `#8fb4f0`, Grok X `#c9c3e8`, Local L `#f3e9b5`, Other + `#b79be8`.

All text passes WCAG AA; the lowest pair is 5.6:1. Control borders are at least 3:1.

## Type

- **Atkinson Hyperlegible Next** for all reading text: chat, lists, buttons, fields. Body 15px.
- **Pixelify Sans** (ligatures off) only for headings, hob names and uppercase section labels, never below 14px.
- Fonts are bundled with the app; no network font loading.

## Shape and motion

- Pixel corners (a 4px clipped corner) on cards and buttons. Primary buttons have a 4px "press" edge and press down 2px.
- Focus is a 3px moonlight ring; inside clipped shapes it is drawn inset.
- Selection uses a fill (`#2c2a5a`), never a colored left edge. **No decorative left-edge accent borders** anywhere.
- Motion is stepped (pixel timing): hover a hob and it hops; working hobs bob; thinking shows blinking dots; streaming shows a moonlight caret; new messages, and the line that says how a reply ended (stopped, cut off, limited or failed), slide in; approve throws sparkles, deny shakes, forget poofs, sleep shows Zs. **Every animation stops with Reduce motion.**
- Each hob is a 14×14 pixel avatar generated from a seed (hat, gear, face, ears, beard, outfit, skin) plus one of six colors (Violet, Moss, Amber, Rose, Sky, Ember). The seed and color are saved with the hob, so the same hob looks the same on every device. The Hobbots mark, on the rail and the app icon, is the chief of the hobs: a 20×20 elder hob built from the same parts, in a gem crown with a lantern staff. On the rail the chief keeps still and its lantern speaks for the hobs: it looks around once when the app opens and on hover; while any hob works the lantern burns brighter with a slow flicker; while a request waits in the Inbox it raises a blazing amber lantern that pulses, shows a "!", links to the Inbox and says how many requests wait. With Reduce motion the colors, raised lantern and "!" stay and nothing moves. The needs-you mood follows the Inbox live: it shows as soon as a request arrives and ends once every request is decided; its link reads "Hobbots inbox, a request needs you" or "Hobbots inbox, 3 requests need you", and otherwise "Hobbots home". In a development build, `?chief=idle`, `?chief=working` or `?chief=needs-you` previews a mood. The sprite sheet defines nine states: idle, working, thinking, waiting, needs you, asleep, celebrating, failed, sending.

## Layout

- **Title strip**, 30px, with the window controls.
- **Rail**, 76px: the chief of the hobs, Home, Hobs, Inbox (needs-you count), Usage, and Settings at the bottom. Icons are 12×12 pixel art; the active item is moonlight on line.
- **Hob panel**, 256px: search over hobs, threads and messages, whose results replace the hob list while a search is typed; "Hobs" label; each hob row (sprite, name, role · live thread count, or "On Aldric's quest" linking to the Quest while it works on another hob's Quest) opens into its threads, each with a ⋯ menu on hover and focus; "+ New thread"; "Archived · N" when the hob has archived threads; a "Rooms: the great hall" card tagged Later; "+ Summon a hob"; key hints. Collapses.
- **Chat**: header with sprite, name, thread title, role, a ⋯ menu with Archive thread, brain chip (the runtime's tile, runtime · model · effort, and health), which in a thread opens the brain picker: each runtime with its models, or why it cannot think now; the efforts the current model takes, as a segmented row; "Also make it <Hob>'s default"; "Back to <Hob>'s default" when the thread has its own brain. Where a reply's brain differs from the reply before it, the transcript shows a centered note, "Now thinking with Codex · <model>", and after a switch before the next reply, "The next reply thinks with …". A limited or cut-off reply offers "Continue with <runtime>" for each other ready runtime beside Continue from here, Edit hob and the right-panel toggle. My messages are right-aligned on a line-colored bubble (max 460px); a hob's messages show its 26px sprite and name in moonlight. A new thread shows "A fresh page" with idea chips. Above a hob's reply, its steps sit in a panel box with a line border: ✓ done in mint, a blinking ● running in lantern, ◷ waiting for approval in lantern, ✗ failed and ⊘ not allowed in rose (with the reason under it, saying whether the hob's permissions, you or the sandbox refused it), ■ did not finish in label, and a bold ? in lantern for a tool call cut off while it ran, with "Cut off while it ran, so it may or may not have taken effect. Hobbots won't run it again. Check it before you continue." under it and, when opened, when it started. A command step's label reads what the command does: it leaves out leading `VAR=value` assignments that only set how output looks or switch a config file off, such as `GIT_CONFIG_GLOBAL=/dev/null` or `NO_COLOR=1`, and keeps any other, cuts a path of four parts or more to its last two (`…/src/app.ts`), and when the whole command is one Git command it leaves out `-C`, since the step names that folder. A push, which the step names by remote and branch, and a Git command with `--git-dir` or `--work-tree`, which is decided on more than one folder, keep every folder option. A tool step opens to show the tool, the action in the Permissions tab's words and what it acted on, then its Output on deep with a line border, in monospace, with secrets already redacted. Short output shows whole. Long output shows its first lines, a dashed line saying "148.9 kB left out here", and its last lines, which open scrolled to the end where an error usually is; each part scrolls past 240px. Under it, "Open the full log (165 kB)" in lantern opens the whole redacted log in the browser, or "The full log could not be kept." in label. A finished reply keeps its tool steps and drops its thinking. A step waiting for approval has its approval card under the steps, ringed in lantern: the hob's sprite and "<Hob> asks permission", when it expires, then the action in the Permissions tab's words with the exact command or path, what it acts on, who asked, why now and the risk; Allow once (approve) and Deny (deny). A high-risk request (a force push or a push to the default branch) shows "High risk · once only" in rose under Risk and a check box, "I checked this action. Let <Hob> do it this once.", which enables Allow once. Deny opens an optional reason with Deny and Cancel and Escape closes it. Once decided the ring turns mint with a pop for Allowed, rose with a shake for Denied with the reason, or label for Expired, and the buttons give way to that line. Composer: a plain-text input on deep with a control border, Send in lantern, Stop in rose, hint line. It takes no Markdown and shows no formatting toolbar: what is typed or pasted is sent as is, with every line break, tab, space and blank line, and pasted rich text keeps only its text. A draft of only whitespace is not sent. It grows with its text to 160px, then scrolls, and the transcript keeps its last message in view while it grows. Enter sends, Shift+Enter adds a line, and Enter that ends an IME composition never sends. The input clears as soon as a message is sent and keeps focus after sending and when a reply ends; a refused send puts its text back. Each thread and fresh page keeps its own unsent draft, also across a reload, and Up on an empty input brings back the last message sent in the thread to edit. The hint reads "Enter sends · Shift+Enter adds a line · ↑ brings back your last message". Stop ends only the current reply; Cancel lives on the Quest. Under a request that started a Task, a Task card sits in the transcript (the Quest card once a party joins), ringed in control, lantern while something needs you, mint once done and rose once failed: the owner's sprite and "Aldric is on it" (then "Aldric finished this"), the Task's title, "1 of 2 done" with a mint progress line, the party's sprites with "Aldric's party: Quill and Ada" for a Quest, and at most four rows (status square, owner sprite, Task or step title, the owner and what it waits on or last reported, and a status tag), ordered needs you, failed, blocked, running, waiting, with done rows folded into a count, more rows counted, and Show all. A Task with steps shows only its current step and "step 3 of 7". While work runs, a strip under the chat header shows "Aldric's quest" with the lead's and the party's sprites and counts ("1 needs you", "1 running"), never rows, and it leaves once the work ends. A row, the strip or Show all opens a drawer over the end of the chat, 420px with a control edge: Back to the Task above, the Task's status and owner, "Aldric gave it" with the brief, its milestones, the Tasks under it, its checkpoints (time, kind tag and what was reported), its questions with their answers, its output and what was handed to it, then "Tell Aldric about this task", which sends your note to the lead's chat as "About "<Task>": <note>". The open Task is in the address (`?task=`), its title takes focus, and Escape or Close shuts it. The chat itself gains only the moments that matter: a question that reached you ("Ada asks you", ringed in lantern, with your answer box, then "You answered: …" in mint), a quiet line when the lead answered a member for you, and the lead's wrap-up.
- **Right panel**, 340px, tabs **Quest**, **Inbox**, **Workshop**. Quest: the control room, one section per request's Task tree, a Quest pinned from another thread first (with "Pinned from another thread" and Open its thread), then this thread's own, newest first. Each has its title in Pixelify, a Pin chip (Pinned in moonlight, pressed) that keeps it visible in every thread on this device (a pinned Quest the hub no longer has says so with Unpin; one that could not be read says so with Try again and stays pinned), "Aldric's quest · 1 of 2 done", one block per Task filled mint when done, and the full Task tree: each Task indented under its parent (nested Quests under their member, tagged Leads a quest), with its status square, owner sprite, "<owner> · <Task>", who it waits on in lantern ("waiting on Quill and you", from its dependencies, its owner's wait and its open questions), its age, and a status tag, with Cancelling… and Cancelled apart from Done. A row opens the Task in the drawer, even for a pinned Quest from another thread, and is marked with a line fill while open. Under the tree, the open Task's owner, title and attempt, with the controls that apply to it: Retry on a failed Task, Reassign on a member's Task, Cancel Task on any Task under the top one that has not ended; then Cancel Quest (Cancel Task for a request with no party, Cancelling… until every Task confirms). The controls act on the Task directly, never through the lead, and stay disabled, with "Retry, Reassign and Cancel arrive once the hub can confirm what each one did.", until the hub confirms their outcomes ([#311](https://github.com/otaviobarros/hobbots/issues/311)). Inbox: this Quest's questions, approvals, problems and results with delivery state. Workshop: the live night scene with a link to the Workbench. Collapses.
- **Reconnecting banner**: lantern fill, "Reconnecting to Hobbots…"; messages wait to send.
- **Toast**: a card on Card with a Line 2 border, above the composer, with one action (for example Undo) as a secondary button. It is a polite status and stays 8 seconds, longer while hovered or focused. A refusal uses a lantern border; a failure uses rose.

## Components

The component sheet defines: buttons (primary, approve, secondary, deny, quiet, disabled, icon, chip), switch, segmented control, inputs, status tags, Workbench view labels, delivery steps (Sent, Delivered, Read, Answered), the approval card (Allow once, Always for this site, Deny, Details), Task and Quest card, nested task rows, the Quest strip, the Task drawer, provider tiles, potions, hop / sparkles / poof, the streaming caret, the banner, the menu and the toast. Shared primitives live in `packages/ui` (shadcn/ui, restyled to these tokens).

## Behavior rules

- Durable server records drive every status; persuasive assistant text never does.
- Workbench labels are honest: Live, Screenshot (with age), History, Unavailable (and why). Computer control is shown as Later.
- Approvals show the exact action, target, who asked (for example You → Pip → Tinker), why now, risk and expiry. Lifetimes: once, this Quest, always for this site; high-risk actions offer once only and need a check box. Deny takes an optional reason. Expired requests cannot be approved late.
- Retire asks what happens to a hob's work (hand it off, let it finish, stop it now). Nothing is deleted; the hob moves to Settings › Archived hobs.
- Archiving a thread never asks first and never deletes: a toast offers Undo, and Restore brings it back at any time. An archived thread leaves the hob panel, stays in search with an Archived tag, and opens read-only with no composer. Archive is disabled, with its reason, while the thread has a running or queued reply or a pending approval, so it never interrupts work. The hub's archived time drives the Archived state on every device.
- Closing the window keeps Hobbots in the menu bar by default; Settings › General lets the user change that and turn off Open at login. With it off, closing the last window while hobs work first says that their work will stop.
- A hob's reply is formatted from its Markdown: headings in Pixelify Sans and moonlight, square list markers, tables with 2px line borders and a panel header row, quotes on a panel fill (never a left-edge accent), inline code and code blocks in the monospace font on the deep ground. A code block names its language and has a Copy button; code is highlighted with the palette (keywords lantern, strings mint, numbers rose, names moonlight, types star, comments label). HTML in a reply shows as text. A link opens in the browser and shows its address beside its text. An image loads only after the reader presses "Show image from <host>", and only from an `https:` address. While a reply streams, a table appears only once its header is complete and a row only once it ends, so raw pipes never flash. Your own messages stay plain text, exactly as typed.
- Providers appear only when connected; keys typed by hand go to the OS keychain and never into chat.
- Connections that give a hob abilities beyond its runtime's own tools are called **Charms**: integrations with other apps and services (GitHub first, with Push; later Slack, Google Drive, any MCP server). They are connected once and granted per hob. The hob profile's tabs are Profile, Charms and Permissions. Rules show Allow, Ask or Never; a rule Hobbots can only check, not enforce, says so.
- A hob running without the sandbox shows the Unsandboxed tag on its profile, chat header, Workbench header and Home tile. Turning the sandbox off asks for a confirmation check box.

## Implementation status

The validation slice ([ADR 009](../decisions/009-toolchain-and-validation-slice.md)) builds these screens in this style:

- **Home** is the landing page: the night scene with every hob and its live state, count chips (a hob with a waiting request counts as needs you), Needs you (the first three waiting requests, oldest first, each opening in the Inbox, and how many more wait), Happening now, Recent threads, a Claude potion under AI plans, and Quests in progress (empty).
- **Chat workspace:** title strip, rail (Home, Hobs, Inbox, Usage, Settings), hob panel with search over hobs, thread titles and messages (results show the hob and a snippet of the match, and open the thread scrolled to it), "+ New thread" opening a fresh page with idea chips (the thread is saved on the first message), ⌥↑ / ⌥↓ to switch threads, chat with streaming, replies formatted from Markdown, thinking, Stop, stopped and failed states, a reconnecting banner, and the right panel with Quest, Inbox and Workshop tabs. Quest and Inbox show empty states; the Workshop scene follows the hob's live state.
- **Inbox:** a 380px list beside the selected request. The list has a mailbox header whose flag pulses while requests wait, then Needs you (pending requests, oldest first, with their count) and All (newest first) as tabs. Requests are grouped by hob and thread until Quests exist; each shows "Hob → you", an Approval or Expired tag, the operation, the exact action and its status (how long it has left, or how it ended). The detail shows the thread, when it was asked, when it expires and when it was decided, then the chat's own approval card, so deciding works the same in both places, with Open in the chat. The request shown goes into the address, so once it is decided, here or in the chat, it stays in view with its outcome until you pick another, and "expires in" counts down while the page is open. History lists the latest 200 decided and expired requests, most recently decided first, with their verdict (Once, Always, Denied, Expired). The tab and the request are in the address. The rail's Inbox item shows the count of waiting requests, except on the Inbox itself.
- **Standing rules** are listed at the top of Inbox History, above the decisions, and in Settings › Permissions under the folders: every "Always" rule that applies now, of every hob, most recently saved first. A row shows the hob's sprite, the rule in the words the card used to save it ("Always let Pip run `pnpm test` in /code/app"), when it was saved and last used, and See the request, which opens the request that saved it in the Inbox. Remove rule (deny style) opens a question in the row, ringed in rose: "Remove this rule? Next time Pip does this, Pip asks you first.", plus, for a site rule, that Pip's running replies stop too; Remove and Keep it, with focus on Keep it, and Escape keeps the rule and returns focus to Remove rule. A removed rule leaves the list, here and in every open window, and so does one the hub revoked because a folder or permission it relied on was taken away. With none, the list says "No standing rules" and how Always saves one.
- **Usage** is an empty page that explains what arrives with the MVP. **Settings** shows General, with "Open Hobbots at login" and what macOS reports for it in the desktop app (waiting for approval in System Settings, or refused), and AI providers: Claude Code health, and the other providers tagged Later.
- Summon, Edit hob and Rooms are disabled or tagged Later. Hobs are seeded avatars stored with each hob (migration `0002_hob_look`).
