# Hobs read web pages through the hub, decided per site and by where the URL came from

- **Date:** 2026-11-08
- **Issue:** [#1267](https://github.com/otaviobarros/hobbots/issues/1267)
- **Pull request:** PR_LINK
- **Commit:** COMMIT on `claude/project-thread-7hl8qc`
- **Setup:** Linux x86_64 container (Node 22), hub from source on SQLite and PostgreSQL 16, with the fake runtime. A local test site on loopback stood for public and private addresses: a static resolver gave its names addresses from TEST-NET-3 (`203.0.113.0/24`), `10.0.0.8` and `127.0.0.1`, and only the fetcher's test-only `dialAs` mapped the checked public address to the loopback server, so the policy decided what it would in use. The clean-runtime contract tests ran against an installed Claude Code 2.1.319 and Codex 0.167.0 (`@openai/codex` from npm), each with a stand-in model and no account. Libraries: `@mozilla/readability` 0.6.0, `linkedom` 0.18.15, `turndown` 7.2.5, `@joplin/turndown-plugin-gfm` 1.0.68, `robots-parser` 3.0.1, Effect 4.1.0. The library comparison used `defuddle` 0.19.6.
- **Result:** Passed with gaps. Every "Done when" case of #1267 holds at hub level and in the contract tests, except that a step cannot ask (ADR 018), so a URL a hob wrote into a step brief is held for you rather than asked about; no real model and no real site were used.

## Readability or Defuddle

ADR 036 left the choice of page-to-text library to this issue. Both ran on the same saved pages, on linkedom 0.18.15, with Defuddle set to `markdown: true` and `useAsync: false`:

| Page | Readability 0.6.0 + turndown 7.2.5 | Defuddle 0.19.6 |
|---|---|---|
| Node.js 24.0.0 release notes (547 KB) | The whole changelog, 82,606 characters, headings and lists kept; title from the page's `<title>` | The same text, 81,048 characters, with the post's own heading |
| Node.js DNS API docs (228 KB) | The whole page, 75,635 characters, code kept; the page has an empty `<title>`, so no title | The same, with code fences marked as JavaScript and the stability notes kept |
| Node.js blog listing (820 KB) | Picks the footer as the article (1,207 characters); the 46 links still list every post | The category links and post titles |
| GitHub repository page (312 KB) | The README, 9,412 characters | The README, 9,478 characters |
| Node.js "Introduction" article (91 KB) | The article, 4,534 characters | The article, with its heading |
| Apache License 2.0 (plain text) | Kept as sent | Not run: plain text bypasses both |

Readability is the pick. Both read articles, docs, release notes and a README about equally well; Defuddle did better on a listing page and on code fences. But Defuddle calls itself a work in progress, its default extractors call third-party APIs unless `useAsync` is off, which the hub must never do on its own, and it pulls in more dependencies. Readability is Mozilla's Firefox Reader View code, stable for years, and makes no request. Every link on a page is listed beside the text whatever the article holds, so a listing page Readability reads badly still gives the hob every post to open.

## Gaps

- No real model read a real site: a Claude Code hob and a Codex hob reading pages on the packaged Mac app ([#1272](https://github.com/otaviobarros/hobbots/issues/1272)).
- A step cannot ask (ADR 018), so a step that needs a written URL is held rather than asked; the issue's "asks in the child's session" holds only for sessions that can ask, such as a party member's turn, which was not run here.
- Search results do not yet make a URL found; the runtimes report them in [#1266](https://github.com/otaviobarros/hobbots/issues/1266).
- The read-the-web mark ([#1268](https://github.com/otaviobarros/hobbots/issues/1268)), and the `WebFetched` journal record, limits and the blocked-sites list ([#1269](https://github.com/otaviobarros/hobbots/issues/1269)), are not built.
- A Task brief or Quest goal you edited does not yet add its URLs to the found set; only your messages in the thread do.
