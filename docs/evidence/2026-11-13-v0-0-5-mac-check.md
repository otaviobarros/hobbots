Claude Code 2.1.316 and codex-cli 0.166.0, signed in; `haiku` on Claude Code and Codex's smallest model, at low effort. In the desktop app a camp was made and archived, and a Claude Code hob and a Codex hob each answered a turn. This was a short check, not a full smoke test.

## Gaps

- Migrations 0095 to 0110 did not run during this check, because the real database had already run them. Their run on a real database is the earlier one on 2026-11-12, checked here by its result; there is no database between migration 20 and 0094 to run them on again.
- Run from source, not from the packaged app or the `.dmg`, and on SQLite only.
- Start fresh, chapters, the camp sheet, Find and Ask, and quests in camps were not run by hand. They are covered by the tests ADR 037's Validation section names.

## Findings

- Copying the data folder alone is not enough to move a hub: each hob's runtime files live in `Hobbots-runtimes` beside it, and without them a Claude Code hob reads as signed out.
- A Codex chat from a moved or restored data folder can't continue, because Codex stores each conversation's absolute path; new Codex chats work.
- In a camp, the ⋯ button reads "More for this chat" and its menu "Archive chat".
- Run from source, `/api/health` reports Electron's version, not the app's.
- A hob's brain menu can show Claude Code as signed out while its turns still work.
