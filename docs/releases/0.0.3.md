# Hobbots 0.0.3 beta

The third beta of Hobbots, for macOS on Apple silicon and Intel, and now for Linux. Its headline is skills: one library of skills you import, write or let hobs propose, given to every hob, a project or one hob, and delivered to Claude Code and Codex alike. This beta also makes "done" mean delivered, runs every hub tool through one pipeline that Charms plug into, and packages Hobbots for Linux. It is still an early build, so back up your data before you rely on it. The [status page](../STATUS.md) lists what has been proven end to end and on which setup.

## Install or update

**Mac.** Download the `.dmg` for your Mac from the release and follow [Install the Mac app](../../README.md#install-the-mac-app). Coming from 0.0.2, quit Hobbots and drag the new app onto Applications, replacing the old copy. Your threads, memory and settings stay in `~/Library/Application Support/Hobbots`, and the hub backs them up before it updates its database. The app is still not signed by an Apple developer, so macOS may ask you to choose **Open Anyway** again.

**Linux.** Download the package for your system and follow [Install on Linux](../../README.md#install-on-linux): a `.deb` for Ubuntu 24.04 and Debian or an `.rpm` for Fedora, each for x64 and arm64.

The requirements have not changed: at least one runtime, installed and signed in: [Claude Code](https://code.claude.com/docs/en/setup) 2.1.301 or later with your Claude plan, or [Codex](https://developers.openai.com/codex/cli) 0.166.0 or later with your ChatGPT plan. On macOS, version 13 Ventura or later.

## What is new

- **The Skills page.** A library of skills that every hob can use. Import a skill from a folder or a Git repository, write one yourself, or choose **Add a skill › Write one** and draft it with a hob. Each save is a new revision that you roll out, keep a hob on an older one or roll back from **What changed**.
- **Skills for every hob, a project or one hob.** Give a skill to Everyone, to a project or to a single hob, from the Skills page, a hob's new **Skills** tab, its profile or Summon. The narrower scope wins, a clash between two projects is shown, and a hob can turn a shared skill off for itself alone.
- **The same skills on Claude Code and Codex.** Each turn gets exactly the skills its hob was given, delivered the way each runtime loads its own, and nothing else from your home folder. Skills in `~/.agents/skills` are read as they are and never changed by Hobbots; **Make a copy** gives you one you can edit.
- **Plugins as skill sets.** A plugin, or a folder of skills that share files, comes in as one set with one revision, keeps its links between skills working, and can be exported again as a plugin. You can copy one of its skills out on its own.
- **See which skills a reply used.** A reply names each skill it used and its revision, with **Open**, and a skill's **Activity** counts its uses by hob and chat.
- **Hobs propose skills.** A hob can draft a new skill or a change to one. Its proposal waits for you in **To review** and the Inbox, where you take it as it is, edit it first or turn it down.
- **Skills in backups, exports and Diagnostics.** A backup holds every skill revision and where it is used. **Skills › Export…** saves the library or a set with a `skills.lock.json` that another hub can import, and Diagnostics lists each hob's skills by name and revision, never their content.
- **Done means delivered.** A member's Task shows Done only once the files it was asked for are inside its folders, never on its reply alone, and a Quest completes only when its lead says it delivered. A lead is held to the files your request names, so it can't call a Quest delivered somewhere you never agreed to.
- **Leads leave their members' work alone.** A lead can't commit changes a member's open Task left uncommitted, and milestones are credited to the hob whose work reached them.
- **What a reply is waiting on.** While a reply waits on an approval or a long command, it says what it is waiting on, and **Stop waiting** lets it carry on without it.
- **One pipeline for every hub tool.** The GitHub Charm, Local Git, Memory and Skills are decided, asked, recorded before they run, sent once and redacted the same way. GitHub reads now follow your policy and grants like every other action, and taking a Charm away from a hob stops its running turn. Charms are now registered in one place and granted to a hob by id, which makes room for the next ones.
- **Linux packages.** Hobbots now ships `.deb` and `.rpm` packages for x64 and arm64. Installing one also installs what the tool sandbox needs on Linux.

## Fixes

- Start over on one hub no longer signs every other hub on the same computer out of GitHub: each hub keeps its own keychain items ([#1214](https://github.com/otaviobarros/hobbots/issues/1214)).
- A lead can no longer complete a Quest as delivered at a destination you never agreed to ([#1215](https://github.com/otaviobarros/hobbots/issues/1215)).
- A member's Task no longer shows Done when its reply says the work isn't finished ([#1086](https://github.com/otaviobarros/hobbots/issues/1086)).
- A lead no longer commits a member's work under its own identity ([#742](https://github.com/otaviobarros/hobbots/issues/742)).
- A hob can read the full output its runtime saved for a long command in its own session, and nothing else can write to it or read it.
- Stuck Task controls agree across the Task card, the lane and the Inbox.
- The Inbox's keys and its **Always** label fit the request they answer, and `hand_off` and `wait_for` are steered to the right ids.
- Watching `~/.agents/skills` survives a folder being replaced by a file, importing the same skill twice quickly imports it once, and skill folders stay removable with their data folder.
- Help's plain check names the memory engine, and a backup's summary lists its skills.

## Known limits

- **Unsigned app.** Hobbots is not signed or notarized by Apple, so macOS blocks the first launch until you choose Open Anyway, and a new version may ask again ([#945](https://github.com/otaviobarros/hobbots/issues/945)).
- **No automatic updates.** To update, replace the app with the one from the new `.dmg`, or install the new Linux package over the old one.
- **Linux and Intel Macs are checked in CI only.** Each package is installed, launched and quit on its own architecture in the release workflow, but only macOS on Apple silicon has been checked by hand with real hobs. Opening at login is macOS only.
- **Commit identity.** When your Git config sets no name and email, a hob may try to set one itself on its first commit, which the hub refuses ([#1213](https://github.com/otaviobarros/hobbots/issues/1213)).
- **A lead can answer an approval meant for you.** A member's command that asked you for approval can be approved by its lead ([#1216](https://github.com/otaviobarros/hobbots/issues/1216)).
- **Stop waiting on Claude Code.** After **Stop waiting**, a Claude Code hob may start the same command again in the background ([#1217](https://github.com/otaviobarros/hobbots/issues/1217)).
- **Workbench Changes.** Work done in an Attempt that was killed is on disk and in the commit but missing from Changes ([#1218](https://github.com/otaviobarros/hobbots/issues/1218)).
- **Skills.** Checking a skill's source for updates, trying a skill in a chat and importing a repository's own skills are not built yet ([#1097](https://github.com/otaviobarros/hobbots/issues/1097), [#1098](https://github.com/otaviobarros/hobbots/issues/1098), [#1099](https://github.com/otaviobarros/hobbots/issues/1099)).
- **Browser use and hobs managing other hobs** are not built yet.
