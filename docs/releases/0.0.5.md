# Hobbots 0.0.5 beta

The fifth beta of Hobbots, for macOS on Apple silicon and Intel and for Linux. Its headline is chat and camps: each hob now has one chat that never ends, split into chapters, plus camps, one per goal. A long chat no longer gets slower and more expensive with every turn, because each new chapter starts from what was decided, made and left open rather than from the whole transcript. Decisions and artifacts are kept as records you can find and ask about, and quests live in the camp that started them. It is still an early build, so back up your data before you rely on it. The [status page](../STATUS.md) lists what has been proven end to end and on which setup.

## Install or update

**Mac.** Download the `.dmg` for your Mac from the release and follow [Install the Mac app](../../README.md#install-the-mac-app). Coming from 0.0.4, quit Hobbots and drag the new app onto Applications, replacing the old copy. Your threads, memory, skills and settings stay in `~/Library/Application Support/Hobbots`, and the hub backs them up before it updates its database. The app is still not signed by an Apple developer, so macOS may ask you to choose **Open Anyway** again.

**Linux.** Download the package for your system and follow [Install on Linux](../../README.md#install-on-linux), then install it over the old one.

**What happens to your threads.** On its first start, 0.0.5 makes each hob's most recent open thread its chat, and turns every other thread into a camp with the same title. Nothing is deleted, archived threads stay archived, and skill trials stay camps.

The requirements have not changed: at least one runtime, installed and signed in: [Claude Code](https://code.claude.com/docs/en/setup) 2.1.301 or later with your Claude plan, or [Codex](https://developers.openai.com/codex/cli) 0.166.0 or later with your ChatGPT plan. On macOS, version 13 Ventura or later.

## What is new

- **One chat per hob, and camps.** The sidebar lists each hob's **Chat**, then its camps, pinned ones first, and **Make a camp**. A camp has a name, a goal and can be **Private**, which keeps it out of memory entirely. Opening a hob opens its chat, and the old New thread button is gone. **Start a fresh chat** in the chat's menu starts over and carries what is still open (questions, Tasks, waiting work) into the new chat.
- **Chapters.** A chat's transcript is split into chapters, one per topic, shown with a divider. A hob can start a new chapter itself with `start_chapter`. Each new chapter starts a new runtime session from a context pack: the camp's brief, the decisions that hold, the open work and the previous chapter's summary, never the old transcript. On a scripted 200-message chat, the last topic's turns started with about 86% fewer tokens ([evidence](../evidence/2026-11-12-context-pack-tokens.md)). A hob reads an older message in full with `read_message` when it needs one. You can also split or merge chapters by hand, and the **Focus** chip shows what the turn started with.
- **Camp suggestions.** When a topic in the chat grows, Hobbots suggests a camp for it. **Make it a camp** moves that chapter, with its messages, decisions, artifacts, open questions and quests, into a new camp and leaves a stub in the chat. A chapter divider's menu offers the same.
- **Decisions and artifacts as records.** Hobs record decisions with `record_decision`, and every decision and artifact names who made it. A changed decision keeps the old one, crossed out. A camp's sheet (**This camp** in its header) has an Overview with the camp's brief, quests and chapters, a Decisions tab, an Artifacts tab grouped by kind with each file's versions and a To review tag, and **Mine** with your pins and notes to self.
- **Find and Ask.** Find searches decisions, artifacts and chapters by their words. **Ask** answers a question such as "where did we decide X" from those records and cites the message each came from. A private camp is found only from inside it.
- **Notes to self, pins and catch-up.** A **Note to self** is a message no hob reads or answers. Pin any message from its menu. Coming back to an unread chat shows **While you were away**, with the replies, decisions, artifacts and quest changes since you left.
- **The hub's brain.** Settings and setup let you pick the model the hub itself uses for briefs, chapter summaries, camp suggestions and Ask, from every runtime you are signed in to, or **No AI**. Under No AI, briefs and summaries are written from rules and no model is called.
- **Quests in camps.** A quest belongs to the camp that started it. Its status shows as a pill in the camp's header and opens the quest in the camp's sheet, which replaces the Quest room's lanes. A quest that moves with its chapter moves whole, even while it runs, and keeps reporting in the camp.
- **The claims register.** The hub hands out migration and ADR numbers so two quests never pick the same one, and when two quests touch the same files each lead hears about it and the camp shows a **Heads-up**, without stopping either.
- **Steer and stop running work.** A lead's message reaches a member while it is still working, in the same turn. You can ask a lead to stop its own Quest, and it stops its members and ends the Quest as stopped.
- **Status from the hub.** Hob presence, a thread's run and a Quest's progress now come from the hub, so every window and device shows the same thing. Delivered work you have not reviewed counts as ready for review.
- **Read-only commands.** A hob with Change files set to Never can still run commands that only read, such as `git diff`, `git log` or a test run, when Run commands is Allow. The sandbox makes every write fail.
- **GitHub in delegated Tasks.** A Task's member that holds the GitHub Charm can now use its write operations, under the same approvals as in a chat ([#1343](https://github.com/otaviobarros/hobbots/issues/1343)).

## Known limits

- **The chat screens change again soon.** The next releases bring shared camps with several hobs and people ([ADR 039](../decisions/039-shared-camps.md)). Chapters will then run on their own, so Split, Merge, the Focus chip and Start a fresh chat go away, and a quest will be followed in its card's reply thread instead of the camp's sheet. Your chats, camps, chapters and records carry over.
- **Short check on a real Mac.** This release was not given a full smoke test by hand, since most of its screens are about to change. Its features are covered by automated tests on SQLite and PostgreSQL, on the fake runtime and on installed Claude Code and Codex with stand-in models. A [short check on a Mac](../evidence/2026-11-13-v0-0-5-mac-check.md) ran the update's result on real data and one turn each on signed-in Claude Code and Codex.
- **Moving your data folder.** A Codex chat can't continue after its data folder moves to another path, because Codex keeps each conversation's full path. New Codex chats work. To move a hub, copy `Hobbots-runtimes`, which sits beside the data folder, along with it.
- **Unsigned app.** Hobbots is not signed or notarized by Apple, so macOS blocks the first launch until you choose Open Anyway, and a new version may ask again ([#945](https://github.com/otaviobarros/hobbots/issues/945)).
- **No automatic updates.** To update, replace the app with the one from the new `.dmg`, or install the new Linux package over the old one.
- **Linux and Intel Macs are checked in CI only.**
- **Still open from 0.0.4.** A hob in a plain chat can't ask you a question ([#1330](https://github.com/otaviobarros/hobbots/issues/1330)), a Codex approval can expire when another chat with the same hob finishes ([#1334](https://github.com/otaviobarros/hobbots/issues/1334)), two pages read in parallel on Claude Code can pass a one-page-a-turn limit ([#1335](https://github.com/otaviobarros/hobbots/issues/1335)), and the other findings of the 0.0.4 smoke test, [#1325](https://github.com/otaviobarros/hobbots/issues/1325) to [#1341](https://github.com/otaviobarros/hobbots/issues/1341), are still open.
- **Browser use** is not built yet ([#382](https://github.com/otaviobarros/hobbots/issues/382)).
