# Internationalization standards

Hobbots will be translated. The chosen library is [Paraglide JS](https://github.com/opral/paraglide-js), which compiles each message into a typed function. It is installed when a second language is planned. Until then, these rules keep the message modules in the shape Paraglide uses, so the move is mechanical.

### STD-I18N-001 User-facing copy lives in message modules

Put every user-facing string in a `messages.ts` module in the feature folder, under a stable key. Components read copy from that module and never hold literal user-facing strings.

- ✅ `<h2>{messages.profile.title}</h2>`
- ❌ `<h2>Hob profile</h2>`
- **Why:** adopting a library then means swapping one module per feature, not searching every component.
- **Enforced by:** Biome `noJsxLiterals` with `noStrings`, which also catches attributes such as `aria-label`, `title`, `placeholder` and `alt`. Props that never hold copy, such as `className`, are ignored.
- **Applies to:** `apps/web`, `apps/desktop`, `packages/ui`.

### STD-I18N-002 Messages are whole sentences with placeholders

Write each message as one function that returns a whole sentence and takes its values as named parameters, as Paraglide's message functions do. Never join fragments to build a sentence. Choose plural forms with `Intl.PluralRules`, through the shared `plural` helper.

- ✅ `` summoned: ({ date }) => `Summoned ${date}` ``
- ❌ `"Summoned " + date + " by " + name`
- **Why:** word order and plural rules differ between languages, and a translator cannot reorder fragments.
- **Enforced by:** review.
- **Applies to:** message modules.

### STD-I18N-003 Dates and numbers use shared locale formatters

Format dates, times, relative times and numbers only through the shared formatters in `apps/web/src/lib/format.ts` and `apps/web/src/lib/time.ts`, which take a locale. No other file calls `toLocale*` or `new Intl.*`, or builds date text itself.

- **Why:** one place then decides the locale and the format for every screen.
- **Enforced by:** the frontend check in `pnpm check`, which fails on `toLocale*` or `new Intl.*` outside the shared formatters.
- **Applies to:** `apps/web`, `apps/desktop`, `packages/ui`.

### STD-I18N-004 Layout survives longer text and right-to-left scripts

Use Tailwind's logical classes, which flip in right-to-left scripts: `ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`/`text-end`, `border-s`/`border-e` and `rounded-s`/`rounded-e`. Do not use `ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `border-l`, `border-r`, `rounded-l` or `rounded-r`. Symmetric classes such as `mx-`, `px-` and `inset-x-` are fine. Something that must keep its physical side in every language, such as an arrow that always points right, carries an opt-out (STD-REACT-020). Let text boxes grow with their content. Never put text inside an image.

- ✅ `ms-5`
- ❌ `ml-5`
- **Why:** translated text often runs longer than English, and right-to-left scripts mirror the layout.
- **Enforced by:** the frontend check in `pnpm check`, which fails on a physical class.
- **Applies to:** `apps/web`, `packages/ui`.

### STD-I18N-005 Server and domain code return codes, not display text

Server, domain and adapter code returns error codes and data. Only the client turns them into text for the user.

- **Why:** the client knows the user's locale, and the server does not.
- **Enforced by:** review.
- **Applies to:** `apps/server`, `packages/*` except `packages/ui` and `packages/art`.
