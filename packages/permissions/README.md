# packages/permissions

The policy engine of [ADR 014](../../docs/decisions/014-tool-policy-and-enforcement.md): Allow, Ask or Deny for a normalized operation on a concrete resource (PE-002). The operations, the preset table and the per-hob policy shape live in `@hobbots/domain` (`policy.ts`), so every package reads the same table.

- `PolicyEngine.decide(context, request)` canonicalizes every path and folder, then decides. It never fails: a path it cannot resolve, such as a symlink loop, is denied.
- `evaluate(context, scope, request)` is the pure decision on already canonical paths.
- The answer is the narrowest of the preset, the hob's overrides and every restriction added by the thread, Quest, task or delegation, so nothing can widen it (AG-004, PE-004). A request carries only the operation and its resource, never the model's account of it.
- Each `PolicyVerdict` names the decision, the operation decided (outside-folders for a target outside the hob's folders), a reason code and message, the canonical targets, whether the rule is enforced or only checked, whether an approval is once only or grantable, and the policy version: the rules version plus a digest of every policy input, so an approval can be bound to the exact policy it was given under.

A change to a directory covers everything beneath it. Editing or deleting is denied when the target is, holds or sits inside Hobbots' data folder, or the hooks folder or config file of any Git repository: one at or above the target, one found below a directory target, or one at, above or below any of the hob's folders, wherever its `hooks` link points and whatever folder was approved. Files that the hooks folder's entries link to are protected too. To find every repository, nested ones included, the engine keeps an index of the directories below each of the hob's folders, without following links or entering `.git`. It re-lists only the directories whose modification time, change time, inode or device changed, or that changed too recently to tell. The change time also moves when a modification time is set back, and cannot itself be set. Refreshes of one folder's index run one at a time, and a refresh that fails partway discards the index. On this repository with its dependencies installed (about 160,000 entries), the first decision takes about 1.5 s and later ones about 0.1 s. Past 1,000,000 entries the search gives up: a change in that folder asks instead of following the preset, and changing the folder itself is denied. A repository outside all of the hob's folders whose hooks link into one is not found.

Delete is always only checked, since a permitted command can remove files another way. Push is checked where Run commands and Use the web are both Allow, because a command can push to a remote that needs no credentials; otherwise it is enforced through credential mediation. Every rule is checked for a hob running without the sandbox.

Canonical paths follow the kernel: components are resolved one by one, so `link/..` climbs from the link's target; a dangling symlink resolves to its target; a path that does not exist yet resolves through its nearest existing parent; comparison follows the case sensitivity of the volume, probed on disk without following symlinks (`~/Code` and `~/code` are one folder on a case-insensitive macOS volume). Hosts are normalized as a URL parser would, and loopback, link-local and cloud metadata addresses are denied, including when a public name resolves to one.

Standing grants follow [ADR 015](../../docs/decisions/015-approval-lifetimes-and-grants.md). The context carries the hob's live grants, read again for every call and left out of the policy version. A grant answers only the preset's Ask: never Deny, Never, a high-risk push, a safety Ask, or an Ask from the hob's override or a restriction. Each verdict says whether its Ask is `grantable`, the `rules` Always would save, and for Allow the `grantIds` that answered. Sites are exact: a file's folder (not its subfolders), or for a delete the exact path, since the target may be a folder; a command's literal words in its folder; a host; a push's remote and branch from its folder.

`readCommandLine` is the hub's command reader. It splits a line at `&&`, `||`, `;`, `|` and newlines and returns each simple command's literal words, quotes removed. A line with anything the shell would expand or redirect (globs, `~`, `$`, backticks, `<`, `>`, a lone `&`, backslashes) reads as nothing, and a simple command with a leading assignment, a folder change, a shell or a wrapper such as `env`, `sudo` or `xargs` reads as null. Neither can be granted.

The engine decides; it does not enforce. The runtime's policy hook and the OS sandbox that apply its answers belong to the Claude Code adapter (#131).
