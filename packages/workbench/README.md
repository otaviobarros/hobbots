# packages/workbench

The Workbench's folder scanner and details store of [ADR 023](../../docs/decisions/023-workbench.md). The recorder that uses them, its ports and the read API's helpers live in `@hobbots/agents` (`activity.ts`, `turn-activity.ts`, `activity-reads.ts`).

- `makeFolderScanner()` / `FolderScannerLive` lists a hob's folder as files with their sizes and SHA-256 hashes. It reads files only: it never runs Git or anything else from the folder, so a repository's config, hooks and tools never run. It skips `.git` and `node_modules` in any folder and, in a Git folder only, what its `.gitignore` files and `.git/info/exclude` ignore. A link is listed as a link, with a hash of its target, and is never followed. A file's hash is reused while its inode, size, modification time and change time are the same and it last changed more than two seconds before the scan, so a same-size rewrite that puts its modification time back is still hashed again. Past `maxFiles` or `scanTimeoutMs` the scan stops and says why. Every file it reads, to hash it or keep it, is opened without passing through a link anywhere on its path, in one step, so a folder a command swaps for a link mid-scan is never read through: on macOS the kernel refuses any link on the path (`O_NOFOLLOW_ANY`), and on Linux the descriptor's own path, as the kernel records it, must be the file's path in the folder. Elsewhere the path is checked again after the open, which a swap timed between the two can get past. A folder's names are listed by path, so a swapped folder can show a link's target text, never a file's contents or hash. `read` refuses a path that climbs out of the folder, is a link or passes through a linked folder.
- `makeActivityStore(root)` / `ActivityStoreLive(root)` keeps contents in the data folder's `activity` folder, once per SHA-256 hash, written to a temporary file and renamed, owner-only. It serves a content only when its name is a hash and the file is a regular file with one name that the hub's own user owns, so a planted link or hard link is never read.

Neither knows about Tasks: the recorder decides what to keep, redacts it, and records which Attempt names each content.
